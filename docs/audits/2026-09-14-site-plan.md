## Remote MCP

- [x] Test authentication and subject isolation before implementation, using a
  test-only RSA issuer and real HTTP/MCP requests, not a public no-auth bypass.
- [x] Add a separate HTTP entrypoint: standard SDK Streamable HTTP, bounded
  requests, explicit tool hints, verified JWT issuer/audience/expiry/scope and
  protected-resource metadata. The authorization server remains a separately
  configured OAuth 2.1 provider (authorization code + PKCE S256).
- [x] Reuse the existing stdio MCP worker in separate per-tenant processes with
  individual durable SQLite workspaces on an operator-mounted volume. Never use
  process-global environment mutation to switch concurrent tenants.
- [x] Do not expose local file paths or `furl_read` through public HTTP. Keep the
  host attachment contract, bounds and private stdio/tunnel unchanged.
- [x] Test cross-tenant retrieval, search, list, purge, stats and process restart;
  reject arbitrary tenant identifiers in tool arguments and unauthenticated calls.
- [x] Document deployment configuration and real external launch prerequisites.
  No fake `/mcp`, invented OAuth credentials or unapproved paid infrastructure.
